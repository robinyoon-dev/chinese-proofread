# 설계와 평가

이 문서는 chinese-proofread의 지금 구조를 기준으로 주요 설계 결정과 평가 결과를 요약합니다. 설치 방법과 사용법은 [README](../README.md)에서 설명합니다.

이 플러그인은 결과가 항상 같아야 하는 판별은 코드로 처리하고, 문맥을 이해해야 하는 교정은 별도의 모델에 맡깁니다. 판별, 교정, 작업은 서로 다른 방법으로 평가했습니다.

세부 내용은 다음 두 기록 문서에 있습니다. 두 문서는 작업을 진행한 순서대로 내용을 쌓았으므로, 앞쪽 항목에는 당시 구조를 기준으로 한 내용이 남아 있습니다.

- [설계 결정 기록](design-decisions.md): 판별을 훅에서 코드로 처리한 이유, 판별 설정값을 고른 기준, 교정과 작업을 함께 진행하는 방법처럼 설계할 때 내린 결정을 기록했습니다. 결정마다 검토한 대안과 감수한 트레이드오프를 함께 적었습니다.
- [평가 결과](eval-results.md): 중국어 판별 정확도와 교정 품질을 평가한 결과를 기록했습니다. 평가마다 날짜, 대상 커밋, 모델, 수치를 적어서, 교정 규칙을 고치기 전과 후의 결과를 비교할 수 있게 했습니다.

`docs/`의 `eval-6-3-*` 문서는 교정 품질 평가를 진행하면서 남긴 중간 기록입니다. 평가 결과 문서에서 각 단계의 세부 내용이 필요한 곳마다 이 문서들을 안내합니다.

## 주요 설계 결정

- **판별은 훅의 코드로, 교정은 별도 프로세스의 모델로 처리합니다.** 판별은 입력마다 실행되므로 토큰을 쓰지 않고 결과가 항상 같아야 합니다. (설계 결정 [1번](design-decisions.md#1-언어-판별은-훅에서-코드로-처리하고-교정은-스킬에서-모델이-처리한다), [19번](design-decisions.md#19-교정을-별도-프로세스에서-실행하고-끝나는-대로-훅의-systemmessage로-표시한다))
- **훅은 넓게 감지하고, 교정 에이전트가 교정할 대상을 걸러 냅니다.** 붙여 넣은 로그와 사용자가 직접 쓴 문장을 구분하려면 문맥을 이해해야 하므로, 이 판단은 모델에 맡겼습니다. (설계 결정 [4번](design-decisions.md#4-훅이-넓게-감지하고-스킬이-교정할-대상을-걸러-낸다))
- **판별 설정값은 전체 오탐률 대신 범주별 조건으로 골랐습니다.** "오탐률 10% 이하"라는 처음 기준으로 고른 설정은 `跑local server.`처럼 영어 단어를 섞은 중국어 문장을 놓쳤습니다. 오탐과 미탐의 비용이 범주마다 다르다고 보고 기준을 바꾸었으며, 처음 기준과 바꾼 이유를 함께 기록했습니다. (설계 결정 [12번](design-decisions.md#12-판별-설정값은-전체-오탐률이-아니라-범주별-조건으로-고른다))
- **교정과 작업을 동시에 시작하고, 교정은 끝나는 대로 표시합니다.** 처음에는 교정 블록 없는 도구 호출을 `PreToolUse` 훅이 거부했지만, 이 방식은 대화형 세션에서 동작하지 않았습니다. 훅이 도는 동안 현재 응답이 transcript에 기록되지 않기 때문입니다. 교정을 메인 모델 밖으로 옮기자 모델이 교정을 건너뛰는 문제가 구조적으로 사라졌습니다. 대신 작업 전에 보여 준다는 보장을 포기했습니다. (설계 결정 [17번](design-decisions.md#17-교정-결과를-작업-전에-보여-주고-이-순서를-훅으로-강제한다), [19번](design-decisions.md#19-교정을-별도-프로세스에서-실행하고-끝나는-대로-훅의-systemmessage로-표시한다))

## 평가 결과

정규식 채점자로는 교정 설명의 내용이 맞는지 확인할 수 없으므로, 이 부분은 검증하지 않았습니다.

### 중국어 판별

문장 122개를 조정용 85개와 확인용 37개로 나누어 평가했습니다. 지금의 기본값은 확인용 세트에서 재현율 1.000(27/27), 오탐률 0.500(5/10)입니다. 섞어 쓴 중국어 단어까지 정답으로 계산한 값이며, 판별하기 어려운 문장을 데이터셋에 일부러 많이 넣었으므로 오탐률이 높게 나옵니다.

수치를 읽을 때는 다음 내용을 함께 고려해야 합니다.

- 훅이 한자가 있는 입력에 거의 모두 반응하고 교정 에이전트가 대상을 걸러 내는 구조이므로, 재현율 1.000은 판별이 정밀하다는 뜻이 아닙니다.
- 오탐 5개는 모두 인용하거나 붙여 넣은 중국어입니다.
- 이 확인용 세트는 처음 설정값을 정할 때 이미 사용했으므로, 지금 수치는 독립된 검증이 아닙니다.
- 처음 기본값의 같은 기준 수치는 재현율 0.889(24/27), 오탐률 0.300(3/10)이었고, 섞어 쓴 단어도 교정하기로 하면서 `HANZI_RATIO`를 0.5에서 0으로 낮추었습니다. ([설계 결정 14번](design-decisions.md#14-한국어나-영어-문장에-섞어-쓴-중국어-단어도-교정한다))

세부 수치는 [평가 결과의 판별 정확도](eval-results.md#6-2-판별-정확도)에 있습니다.

### 교정 품질

케이스 40개를 3회씩 실행하고 정규식 채점자로 채점했습니다. 교정 프로세스(Sonnet)의 오류 검출은 45/45, 형식 준수는 349/351, 과잉 교정 없음은 144/144였습니다. Haiku는 오류 검출이 37/45여서 쓰지 않았습니다. 세부 수치는 [평가 결과의 병렬 교정 절](eval-results.md#18-병렬-교정)에 있습니다.

### 작업

같은 케이스에서 메인 모델의 작업 수행은 Sonnet과 Opus 모두 117/117이었고, 메인 모델이 교정 블록을 쓰거나 교정을 언급한 경우는 없었습니다. 대화 응답 언어는 Sonnet 114/117, Opus 115/117입니다.

### 대화형 세션

시나리오 17개를 3회씩 실행한 51회에서 교정 블록의 수와 표시 시점이 모두 기대와 일치했습니다. 인터럽트와 권한 거부 뒤에도 교정 결과를 잃지 않았습니다.

평가에서 통과한 답변 언어는 대화형 세션에서 어긋난 적이 있으므로, 답변 언어는 대화형으로 따로 측정했습니다. 설명을 요청하는 프롬프트 4개를 한국어와 영어 설정에서 5회씩 실행했을 때, 다시 쓰기 전의 최종 답변은 37/40이고 다시 쓴 뒤에는 40/40입니다. 세부 수치는 [평가 결과의 대화 응답 언어 절](eval-results.md#대화-응답-언어-다시-쓰기)에 있습니다.
