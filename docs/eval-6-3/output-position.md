# 교정 결과 출력 위치 수정의 효과 확인

이 문서는 `docs/design-decisions.md`의 13번 항목에 따라 `SKILL.md`에서 교정 결과의 출력 위치를 바꾼 뒤, 그 효과를 확인하려고 Sonnet으로 케이스마다 1회씩 실행한 결과를 기록합니다. 케이스마다 1회만 실행했으므로, 이 문서의 수치는 기준 점수와 같은 조건의 비교가 아니라 수정의 방향이 맞는지 확인하는 참고값입니다. `SKILL.md`를 더 수정할 예정이므로, 두 모델을 케이스마다 3회씩 실행하는 평가는 수정을 마친 뒤로 미루었습니다.

## 실행 환경

- **날짜**: 2026-10-29
- **대상**: 커밋 `e1ced87`에 아래 "바꾼 내용"을 더한 작업 트리입니다. 이 수정은 아직 커밋하지 않은 상태에서 실행했습니다.
- **Claude Code**: 2.1.312
- **모델**: Sonnet 5.5(`claude-sonnet-5-5`)
- **평가 세트**: `evals/quality/cases.py`, 케이스 33개를 케이스마다 1회 실행했습니다. 기준 점수와 같은 평가 세트입니다.
- **실행 명령**:

  ```
  python3 evals/quality/run_eval.py --model sonnet --runs 1 -- -j 2 --max-cost-usd 4
  ```

- **실행 시간과 비용**: 218초, API 환산 $1.66입니다. 실행하는 동안 5시간 한도의 사용률은 14%에서 15%로 올랐고, 주간 한도의 사용률은 12%로 변하지 않았습니다.

## 바꾼 내용

`SKILL.md`만 바꾸었고, 훅의 지시문(`detect_chinese.py`)은 바꾸지 않았습니다. `SKILL.md`만 바꾼 효과를 따로 측정하기 위해서입니다.

- "순서"의 3번과 4번을 바꾸어, 요청을 먼저 수행한 뒤 최종 답변의 맨 앞에 교정 결과를 출력하도록 했습니다.
- "출력 위치" 절을 새로 추가했습니다.
  - 교정 결과는 사용자에게 보이는 최종 답변의 맨 앞에 씁니다. 도구를 사용하는 작업이라면 작업을 모두 마친 뒤에 쓰는 최종 답변의 맨 앞에 씁니다.
  - 도구를 호출하기 전이나 도구 호출 사이에는 교정 결과를 출력하지 않고, 최종 답변에 한 번만 씁니다.
  - 교정 결과를 생각이나 진행 메모에만 남기지 않으며, 교정을 마쳤다고 언급하는 것만으로는 교정 결과를 보여 준 것이 아니라고 적었습니다.
- "요청 수행"에서 "교정 블록을 출력한 뒤에는 곧바로 원래 요청을 수행합니다"를 "교정만 하고 멈추지 않고, 원래 요청을 끝까지 수행합니다"로 바꾸었습니다. 작업 전에 확인해야 하는 경우에는 확인을 요청하는 답변의 맨 앞에 교정 결과를 쓰도록 했습니다.

## 결과

기준 점수는 케이스마다 3회 실행한 값이고, 수정 후의 값은 1회 실행한 값입니다. 실행 횟수가 다르므로 두 값의 작은 차이는 해석하지 않습니다.

| 지표 (모든 텍스트 블록 기준) | 기준 점수 (3회) | 수정 후 (1회) |
|---|---|---|
| 형식 준수 | 0.210 (56/267) | 0.944 (84/89) |
| 과잉 교정 없음 | 1.000 (61/61) | 0.773 (17/22) |
| 작업 계속 수행 | 1.000 (96/96) | 1.000 (32/32) |
| 병음 형식 | 0.317 (19/60) | 1.000 (49/49) |
| 문장부호 설명 없음 (9-1) | 1.000 (6/6) | 1.000 (2/2) |
| 붙여 넣은 부분 교정 안 함 | 1.000 (9/9) | 1.000 (3/3) |
| 대신 쓴 단어 알려 줌 | 0.583 (7/12) | 1.000 (4/4) |
| 영어 그대로 둠 (9-4) | 1.000 (13/13) | 1.000 (8/8) |
| 구어체 유지 | 1.000 (3/3) | 1.000 (2/2) |
| 먼저 확인 | 0.833 (10/12) | 0.750 (3/4) |
| 교정 블록 생략 | 0.917 (22/24) | 1.000 (8/8) |

수정 후에는 모든 실행에서 교정 블록이 최종 답변에 있었으므로, 최종 답변 기준의 결과도 위의 표와 같았습니다.

교정 블록이 출력된 실행 수를 케이스 종류별로 나누면 다음과 같습니다.

| 종류 | 기준 점수: 최종 답변 (3회) | 수정 후: 최종 답변 (1회) |
|---|---|---|
| `fix` | 4/45 | 15/15 |
| `ok` | 6/27 | 9/9 |
| `note` | 1/12 | 4/4 |
| `ask` | 0/3 | 1/1 |
| `none` | 0/12 | 0/4 |

## 결과 해석

- **교정 블록이 최종 답변에 나오게 되었습니다.** 교정 블록이 있어야 하는 29회 모두에서 최종 답변의 맨 앞에 교정 블록이 있었고, 같은 블록을 두 번 출력한 실행은 없었습니다. 교정 블록을 출력하지 않아야 하는 `none` 케이스 4회에서는 한 번도 출력하지 않았습니다. 기준 점수에서 Sonnet의 가장 큰 문제였던 교정 블록 누락은 이 수정으로 해결된 것으로 보입니다.
- **교정 블록이 나오면서 다른 지표도 실제로 검사되었습니다.** 기준 점수에서 낮게 나온 병음 형식과 대신 쓴 단어 알려 줌은, 교정 블록이 없어서 검사할 대상이 없었던 지표입니다. 수정 후에는 두 지표 모두 1.000이었습니다.
- **자연스러운 문장을 고치는 과잉 교정이 새로 나타났습니다.** 과잉 교정 없음의 실패 5건은 모두 `原文`과 `修正` 줄을 써서는 안 되는 케이스입니다.
  - `ok-colloquial`: 구어체 `咋`를 `怎么`로 바꾸었습니다. 사용자의 어조를 유지해야 한다는 규칙과 맞지 않습니다. 구어체 유지 채점자는 `呗`가 남아 있는지만 검사하므로, 이 경우를 잡아내지 못했습니다.
  - `note-keep-bug`: 영어 `fix`를 `修`로 바꾸었습니다. 중국어 표현과 영어 표현을 모두 흔히 쓰는 단어는 영어를 그대로 두고 설명만 덧붙인다는 규칙과 맞지 않습니다.
  - `note-keep-pr`: `PR的规则`를 `PR规则`로 바꾸었습니다. 두 표현 모두 자연스러우므로 고칠 필요가 없습니다.
  - `ok-complexity`: `utils.py里average函数`를 `utils.py里的average函数`로 바꾸었습니다. 고치기 전의 표현도 자연스럽습니다.
  - `ok-no-final-punctuation`: `原文`과 `修正`을 똑같이 쓰고 설명만 덧붙였습니다. 이 경우에는 "고칠 부분은 없고 설명만 덧붙이는 경우"의 형식을 써야 합니다.
- **과잉 교정이 수정 때문에 늘었는지는 아직 판단할 수 없습니다.** 기준 점수에서는 Sonnet이 교정 블록을 거의 출력하지 않았으므로, 교정 블록을 출력했을 때 과잉 교정을 얼마나 하는지 비교할 자료가 적습니다. 기준 점수의 `ok` 케이스에서는 27회 모두 `✅` 줄을 출력했지만, 작업 전에 출력한 `✅` 줄이 대부분이었습니다. 작업을 마친 뒤에 교정 결과를 쓰게 되면서 모델이 문장을 더 꼼꼼하게 다듬으려는 경향이 생겼을 가능성이 있지만, 1회 실행으로는 확인할 수 없습니다.
- **문장부호 설명은 다른 교정이 있을 때만 나왔습니다.** `fix-with-halfwidth-punctuation`에서 "반각 쉼표와 마침표 대신 전각 부호를 쓴다"는 설명 줄이 다시 나왔습니다. 처음에는 이 설명을 실패로 집계했지만, 다른 교정과 함께 나온 문장부호 설명은 허용하기로 정했습니다. 그래서 문장부호 지표는 `docs/eval-results.md`의 "측정 방법"에 적은 대로 바뀐 기준에 따라 다시 집계했습니다.
- **답변 언어가 대부분 한국어로 바뀌었습니다.** `none`을 제외한 29회 중 답변 본문에 한글보다 한자가 많은 실행은 2회였습니다. 기준 점수에서는 87회 중 43회였습니다. 기준 점수와 같은 간이 판정입니다. 한자가 더 많았던 실행 중 하나인 `ask-delete-unused`에서는 `✅` 줄 뒤의 확인 요청을 중국어로 썼습니다.
- **"먼저 확인"의 실패 1건은 기준 점수와 같은 채점자의 한계입니다.** `ask-delete-unused`에서 모델은 파일을 지우지 않고 지울 범위를 확인했지만, 물음표 없이 "也请告诉我"처럼 요청했기 때문에 `ask-question` 채점자에서 실패했습니다.

## 다음 단계

- `SKILL.md`의 수정을 마친 뒤에 Sonnet과 Opus를 케이스마다 3회씩 실행하고, 결과를 `docs/eval-results.md`에 기준 점수와 나란히 기록합니다.
