# 교정 블록 스타일 조사

이 문서는 [#27](https://github.com/robinyoon-dev/chinese-proofread/issues/27)의 조사 결과를 기록합니다. 이 결과에 따른 구현은 [설계 결정 21번](design-decisions.md)에 기록했습니다. 교정 블록이 터미널에서 회색으로 나와 눈에 잘 띄지 않기 때문에, 플러그인에서 스타일을 지정할 수 있는지 확인했습니다.

## 결론

`systemMessage`에 ANSI 색상 코드를 넣으면 대화형 세션에서 색이 적용됩니다. 글자색과 배경색을 줄마다 함께 지정하면 교정 블록 전체를 강조할 수 있습니다. 밝은 테마와 어두운 테마에는 고정한 한 쌍인 `22;38;5;231;48;5;240`을 똑같이 사용하고, 테마는 감지하지 않습니다. 다만 공식 문서에 없는 동작이므로, Claude Code가 업데이트되면 달라질 수 있습니다.

## 회색으로 보이는 원인

Claude Code는 훅 메시지 전체에 회색 글자색을 입힙니다. 이 색은 테마마다 다르며, 어두운 테마에서는 `38;5;246`입니다. 사용자 메시지의 배경색은 Claude Code가 사용자 메시지에만 지정하는 값이고(`userMessageBackground`), 훅이 바꿀 수 있는 값은 아닙니다.

## 시험 방법

- 시험 버전은 Claude Code 2.1.316, 2.1.314, 2.1.312입니다.
- 실제 플러그인과 분리된 시험용 플러그인을 `--plugin-dir`로 불러왔습니다.
- 전용 소켓의 `tmux` 세션에서 대화형으로 실행하고, `tmux capture-pane -e`로 화면에 남은 이스케이프 코드를 읽었습니다.
- 교정 블록은 실제 형식에 긴 설명을 넣어 만들었습니다. 줄이 접히는지 보려고 창 너비를 64칸으로 줄였습니다.
- 테마별 시험은 2.1.316에서 `--settings '{"theme":"..."}'`로 테마만 덮어써서 진행했습니다. 시험 전후로 `settings.json`의 해시가 같으므로 실제 설정은 바뀌지 않았습니다.

## 표현별 결과

| 입력 | 결과 |
|---|---|
| 글자색 `31` | 적용됩니다. |
| 글자색과 배경색 `30;43` | 적용됩니다. |
| 굵게 `1`, 반전 `7` | 적용됩니다. |
| 256색 `38;5;16;48;5;226` | 적용됩니다. |
| 트루컬러 `38;2;…;48;2;…` | 색은 적용되지만 `tmux` 시험에서는 256색으로 바뀌었습니다. |
| 기본 글자색 `39`만 지정 | 적용되지 않습니다. 줄이 회색으로 남습니다. |
| Markdown `**굵게**`, `` `코드` ``, `>` | 렌더링되지 않고 글자 그대로 회색으로 나옵니다. |
| 구분선, 이모지 | 그대로 나옵니다. 색은 회색입니다. |

`39`가 적용되지 않으므로 회색을 없애려면 글자색을 직접 지정해야 합니다. 스타일이 끝나는 지점 뒤의 글자는 회색이 아니라 기본 글자색으로 나오기 때문에, 한 줄의 일부만 칠하면 같은 줄의 색이 나뉠 수 있습니다.

## 표시 환경별 결과

아래 결과는 줄마다 `97;48;5;238`을 지정한 블록과, 제목 줄에만 `30;43`을 지정한 블록으로 확인했습니다.

| 환경 | 결과 |
|---|---|
| `PostToolUse`, `Stop` 훅 | 둘 다 적용됩니다. |
| 접힌 줄 | 접힌 다음 줄까지 스타일이 이어집니다. |
| 창 크기 변경 | 유지됩니다. |
| `ctrl+o` 상세 보기 | 유지됩니다. |
| `--resume`으로 다시 불러온 세션 | 유지됩니다. 이스케이프 코드가 transcript에 저장되기 때문입니다. |
| 2.1.312, 2.1.314 | 적용됩니다. |
| `-p` 텍스트 출력 | 블록이 출력되지 않으므로 영향이 없습니다. |
| `-p --output-format stream-json` | 코드가 제거된 텍스트로 전달됩니다. 줄마다 `Stop says: `가 붙습니다. |
| `NO_COLOR=1` | Claude Code가 코드를 제거하지 않아 색이 그대로 나옵니다. |
| `FORCE_COLOR=1` | 256색 코드가 낮추어지지 않고 그대로 전달됩니다. |

## 테마별 결과

`dark`, `light`, `dark-ansi`, `light-ansi` 테마 모두에서 글자색과 배경색이 지정한 값 그대로 출력되었습니다. 달라지는 것은 Claude Code가 입히는 회색입니다.

| 테마 | 훅 메시지의 글자 스타일 |
|---|---|
| `dark` | `38;5;246` |
| `light` | `38;5;241` |
| `light-ansi` | `90` |
| `dark-ansi` | `2`와 `37`의 조합 |

- `dark-ansi`에서는 흐림(`2`)이 함께 입혀지므로 지정한 흰 글자도 흐려집니다. 코드 앞에 `22`를 붙이면 흐림 코드가 출력에서 사라집니다.
- `Stop says: `는 첫 줄에 붙고 스타일이 적용되지 않습니다. 블록 앞에 빈 줄을 넣으면 이 문구가 혼자 한 줄을 차지하므로 블록의 시작 위치가 맞습니다.

## 스타일 후보 비교

대비값은 직접 계산한 값이며, 어두운 배경은 `#1e1e1e`, 밝은 배경은 `#ffffff`로 가정했습니다.

| 후보 | 글자 대비 | 블록과 어두운 배경의 대비 | 블록과 밝은 배경의 대비 | 판단 |
|---|---|---|---|---|
| 글자 `97`, 배경 `238` | 9.7 | 1.71 | 9.74 | 어두운 테마에서 눈에 덜 띕니다. |
| 글자 `231`, 배경 `240` | 7.1 | 2.34 | 7.11 | 채택했습니다. |
| 글자 `231`, 배경 `24` (파랑) | 7.0 | 2.37 | 7.03 | 사용자 메시지와 구분하고 싶을 때 사용할 수 있는 대안입니다. |
| 반전 `7`만 지정 | 5.5~6.1 | 해당 없음 | 해당 없음 | 테마와 터미널이 어긋나면 2.7~3.0으로 떨어집니다. |
| 굵게 `1`만 지정 | 회색 그대로 | 해당 없음 | 해당 없음 | 회색이 그대로 남으므로 제외했습니다. |

`97`은 터미널의 색 팔레트에서 바뀔 수 있으므로 흰색이라고 장담할 수 없습니다. 256색의 231번은 팔레트를 바꾸어도 보통 그대로 유지되므로 `38;5;231`을 사용합니다.

## 테마를 감지하지 않는 이유

- 터미널의 배경색을 읽으려면 터미널과 직접 통신해야 하는데, 훅에서 사용할 수 있는 방법이 없습니다.
- `settings.json`의 `theme`은 읽을 수 있지만 값이 `auto`일 수 있습니다. 또한 Claude Code의 테마와 실제 터미널의 배경이 항상 일치하지도 않습니다.
- 글자색과 배경색을 둘 다 고정하면 터미널의 배경과 상관없이 글자의 대비가 유지됩니다. 터미널의 배경에 따라 달라지는 것은 블록이 얼마나 눈에 띄는지뿐입니다.

## 쓸 수 없는 경로

- `terminalSequence`는 알림과 창 제목용 시퀀스만 허용하고 색상용 CSI 시퀀스를 거부합니다.
- `/dev/tty`에 직접 쓰는 방식은 문서에서 지원하지 않는다고 적고 있습니다.
- `additionalContext`는 Claude에게만 전달되어 사용자에게 보이지 않습니다.
- `MessageDisplay`는 Claude의 답변 텍스트만 받습니다. 훅 메시지인 교정 블록은 이 이벤트의 대상이 아닙니다.

## 구현 방향

- **블록:** 배경색은 글자가 있는 칸에만 칠해지므로, 줄마다 공백을 채워 창의 오른쪽 끝까지 칠합니다. 사용자 메시지도 같은 방식입니다. 훅이 받는 `COLUMNS`는 창 크기를 바꾼 뒤에도 현재 폭을 따랐고, 폭은 여기서 들여쓰기 5칸과 여유 1칸을 뺀 값입니다. 긴 줄은 훅이 먼저 접어서 같은 폭으로 칠합니다. `\x1b[K`는 Claude Code가 제거하므로 쓸 수 없습니다.
- **스타일:** 내용이 있는 모든 줄에 `22;38;5;231;48;5;240`을 지정합니다. 배경까지 고정하면 흰 글자가 테마의 배경색에 묻히지 않습니다. 제목 줄만 칠하는 방식은 본문이 회색으로 남습니다. 내용이 없는 줄에는 칠할 글자가 없으므로 코드를 넣지 않습니다.
- **첫 줄:** `Stop says: `와 블록의 시작 위치를 맞추기 위해 블록 앞에 빈 줄을 넣습니다.
- **위치:** `show_result.py`가 `systemMessage`를 만드는 곳에서 메시지를 합친 뒤에 한 번만 스타일을 입힙니다. `FAILED` 메시지에도 같은 스타일이 들어갑니다. `feat/proofread-history` 브랜치의 `history.jsonl`은 그 전에 `proofread_worker.py`가 기록하므로 코드가 들어가지 않습니다.
- **`NO_COLOR`:** Claude Code가 처리해 주지 않으므로 훅이 환경 변수를 확인하고, 설정되어 있으면 스타일과 앞의 빈 줄을 넣지 않아야 합니다.
- **테스트:** `tests/test_parallel_proofread.py`는 `systemMessage`가 블록과 같은지 비교하므로, 스타일을 넣으면 고쳐야 합니다.

## 남은 위험과 미확인 사항

- 문서에 없는 동작이므로 이후 버전에서 코드가 제거되거나 글자로 노출될 수 있습니다. 제거되면 지금처럼 회색 글씨로 돌아가지만, 글자로 노출되면 `[22;38;5;231;48;5;240m` 같은 문자가 블록에 섞입니다.
- `auto` 테마와 실제 16색 터미널은 시험하지 않았습니다.
- 실제 터미널에서는 Windows Terminal의 WSL에서만 눈으로 확인했습니다. 어두운 배경과 밝은 배경 모두 교정 블록이 잘 보였습니다.
- 들여쓰기 5칸은 칠할 수 없으므로 블록은 사용자 메시지와 시작 위치가 다릅니다.
- `COLUMNS`를 훅에 넘기는 동작도 공식 문서에 없습니다. 값이 없으면 가장 긴 줄의 폭에 맞춥니다.
- 표시한 뒤에 창을 줄이면 줄이 다시 접혀 오른쪽 끝이 고르지 않게 됩니다. 창을 늘리면 블록은 표시할 때의 폭을 유지합니다.
