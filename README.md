# chinese-proofread

> 이 플러그인은 아직 개발 중이며, 첫 버전을 배포하지 않았습니다. 교정 규칙과 설정 방법이 예고 없이 바뀔 수 있습니다.

Claude Code에 중국어로 요청을 입력하면, Claude가 그 중국어 문장이 자연스러운지 점검하여 교정하고, 교정된 의미를 기준으로 요청을 수행한 뒤, 최종 답변의 맨 앞에 교정 결과를 보여 주도록 만드는 플러그인입니다.

Claude Code로 개발하면서 중국어를 배우는 한국어 사용자를 대상으로 만들었으므로, 교정 설명은 기본적으로 한국어로 출력합니다. 설명에 사용할 언어는 [설정](#설정)에서 바꿀 수 있습니다.

판별과 교정을 어떻게 설계하고 평가했는지는 [설계와 평가](#설계와-평가)에 정리했습니다.

## 교정 결과 예시

Claude는 교정된 의미를 기준으로 원래 요청을 먼저 수행하고, 작업을 모두 마친 뒤에 쓰는 최종 답변의 맨 앞에 교정 결과를 보여 줍니다. 도구를 호출하는 동안에는 교정 결과를 출력하지 않습니다. 위 이미지에 나온 요청을 입력하면 최종 답변은 다음과 같이 출력됩니다.

```
📝 中文校对
原文: 让这个function跑的更快
修正: 让这个函数跑得更快
설명:
- function은 중국어로 函数(hánshù)라고 합니다.
- 동사 뒤에 정도를 나타내는 보어를 붙일 때는 的(de) 대신 得(de)를 씁니다.
---
(이어서 함수를 최적화한 작업 결과를 설명)
```

설명에서 언급하는 중국어 단어에는 성조 부호로 표기한 한어병음을 덧붙입니다. `原文`과 `修正` 줄에는 두 문장을 쉽게 비교할 수 있도록 병음을 붙이지 않습니다.

중국어로 어떻게 말하는지 모르는 단어는 위 예시의 `function`처럼 영어나 한국어로 대신 써도 됩니다. Claude는 교정 결과에서 그 단어를 중국어로 어떻게 말하는지 알려 줍니다.

이 플러그인의 목적은 중국어 학습이므로, `fix`, `commit`, `edge case`처럼 중국어권 개발자가 영어로도 흔히 쓰는 단어라도 중국어 표현이 있다면 중국어로 바꾸어 알려 줍니다. 다만 다음 단어는 바꾸지 않습니다.

- 코드, 명령어, 파일 경로, 식별자, 약어(`API`, `JSON`, `PR`), 제품이나 서비스의 이름, 브랜치 이름처럼 원래 영어로 쓰는 부분
- `bug`처럼 중국어 문장에서도 영어로 굳어진 단어

## 설치

Claude Code에서 다음 명령을 실행합니다.

```
/plugin marketplace add robinyoon-dev/chinese-proofread
/plugin install chinese-proofread@chinese-proofread
```

훅 스크립트를 실행하려면 `python3`가 설치되어 있어야 합니다.

## 켜고 끄기

중국어 학습과 관계없이 중국어 자료를 다루는 동안에는 교정 기능을 잠시 끌 수 있습니다. 설치 직후에는 기능이 켜져 있습니다.

```
/chinese-proofread:toggle off      교정 기능을 끕니다.
/chinese-proofread:toggle on       교정 기능을 다시 켭니다.
/chinese-proofread:toggle status   현재 상태를 확인합니다.
/chinese-proofread:toggle          현재 상태를 반대로 바꿉니다.
```

- 변경한 상태는 다음 입력부터 바로 반영되며, Claude Code를 다시 시작할 필요가 없습니다.
- 상태는 `~/.claude/chinese-proofread/state.json`에 저장되므로, 모든 프로젝트와 세션에 함께 적용되고 Claude Code를 다시 시작해도 유지됩니다.
- 이 명령은 사용자가 직접 입력할 때만 실행됩니다. Claude가 스스로 판단하여 기능을 끄거나 켜지는 않습니다.

## 설정

환경 변수로 동작을 조정할 수 있습니다.

| 환경 변수 | 기본값 | 설명 |
|---|---|---|
| `CHINESE_PROOFREAD_ENABLED` | (없음) | `0`으로 설정하면 교정 기능을 끕니다. 사용 방법은 [특정 프로젝트에서 항상 끄기](#특정-프로젝트에서-항상-끄기)에서 설명합니다. |
| `CHINESE_PROOFREAD_LANG` | `Korean` | 교정 설명에 사용할 언어입니다. |
| `CHINESE_PROOFREAD_MIN_HANZI` | `4` | 중국어로 판별하는 데 필요한 최소 한자 수입니다. |
| `CHINESE_PROOFREAD_MIN_HANZI_MIXED` | `1` | 영문자가 섞여 있고 한글이 없는 입력에 적용하는 최소 한자 수입니다. `CHINESE_PROOFREAD_MIN_HANZI`보다 크게 설정하면 `CHINESE_PROOFREAD_MIN_HANZI` 값을 씁니다. |
| `CHINESE_PROOFREAD_HANZI_RATIO` | `0.5` | 한자와 한글을 합한 글자 수에서 한자가 차지해야 하는 최소 비율입니다. |

`MIN_HANZI`, `MIN_HANZI_MIXED`, `HANZI_RATIO`가 판별에 어떻게 쓰이는지는 [중국어 판별 기준](#중국어-판별-기준)에서 설명합니다.

숫자를 받는 설정에 숫자가 아닌 값을 넣으면 그 설정은 기본값으로 동작합니다.

예를 들어 설명을 영어로 받으려면 `~/.claude/settings.json`에 다음 내용을 추가합니다.

```json
{
  "env": {
    "CHINESE_PROOFREAD_LANG": "English"
  }
}
```

### 특정 프로젝트에서 항상 끄기

중국어 문서를 다루는 저장소처럼 특정 프로젝트에서는 교정 기능을 항상 끄고 싶다면, 그 프로젝트의 `.claude/settings.json`에 다음 내용을 추가합니다.

```json
{
  "env": {
    "CHINESE_PROOFREAD_ENABLED": "0"
  }
}
```

- 이 환경 변수를 설정하면 `/chinese-proofread:toggle on`으로 켜 둔 상태와 관계없이 기능이 꺼집니다. `status`를 실행하면 환경 변수 때문에 꺼져 있다는 사실도 함께 알려 줍니다.
- 환경 변수를 추가하거나 바꾼 뒤에는 Claude Code를 다시 시작해야 반영됩니다.
- 모든 프로젝트에서 항상 끄려면 같은 내용을 `~/.claude/settings.json`에 추가합니다. 다만 잠시 끄는 용도라면 환경 변수보다 `/chinese-proofread:toggle off`가 더 편리합니다.

## 중국어 판별 기준

입력한 프롬프트가 다음 조건을 모두 만족하면 중국어로 판별합니다. 영문 코드와 식별자는 판별에 반영하지 않으므로, 코드가 섞인 중국어 문장도 중국어로 판별됩니다.

- 한자가 4자 이상 있어야 합니다(`MIN_HANZI`). 다만 영문자가 섞여 있고 한글이 없다면 한자가 1자만 있어도 됩니다(`MIN_HANZI_MIXED`). `跑local server.`처럼 모르는 단어를 영어로 대신 쓴 짧은 문장도 교정하기 위해서입니다.
- 히라가나나 가타카나가 없어야 합니다. 둘 중 하나라도 섞여 있으면 일본어로 보고 제외합니다.
- 한자 수와 한글 수를 더한 값에서 한자가 차지하는 비율이 50% 이상이어야 합니다(`HANZI_RATIO`).

괄호 안의 이름은 각 조건의 기준값을 바꾸는 환경 변수의 이름에서 `CHINESE_PROOFREAD_`를 뺀 것입니다. 위 숫자는 모두 기본값이며, [설정](#설정)에 나온 환경 변수로 바꿀 수 있습니다.

## 한계

- 한글 없이 한자만으로 쓴 일본어 문장은 중국어로 판별될 수 있습니다.
- 설명에 덧붙이는 한어병음은 모델이 생성하므로, 다음자(多音字)나 성조 변화가 있는 단어에서는 성조가 틀릴 수 있습니다.
- 모르는 단어를 한국어로 대신 쓴 문장은 한자가 적으면 중국어로 판별되지 않습니다. 예를 들어 `跑로컬 서버`는 한자가 1자이고 한글이 4자이므로 비율 조건을 통과하지 못합니다. `帮我把로컬 서버跑起来`처럼 한자가 더 많은 문장은 판별됩니다.
- 영어 요청 안에 한자가 한 글자라도 있으면 중국어 입력으로 판별될 수 있습니다. 이 경우에는 스킬이 교정할 대상이 없다고 판단하고 교정 블록을 출력하지 않습니다.
- 한국어 요청 안에 중국어 문장을 길게 인용하면 중국어 입력으로 판별될 수 있습니다. 이 경우에도 스킬의 규칙에 따라, 사용자가 교정을 요청하지 않은 인용문은 교정하지 않습니다.

## 설계와 평가

이 플러그인은 결과가 항상 같아야 하는 판별은 코드로 처리하고, 문맥을 이해해야 하는 교정은 모델에 맡깁니다. 두 부분은 서로 다른 방법으로 평가했습니다.

### 주요 설계 결정

- **판별은 훅의 코드로, 교정은 스킬의 모델로 처리합니다.** 판별은 입력마다 실행되므로 토큰을 쓰지 않고 결과가 항상 같아야 합니다. 스킬의 `description`만 두고 모델이 스스로 스킬을 호출하게 하면 교정이 실행된다고 보장할 수 없으므로, 훅이 지시를 추가하는 방식을 택했습니다. (설계 결정 1번)
- **훅은 넓게 감지하고, 스킬이 교정할 대상을 걸러 냅니다.** 붙여 넣은 로그와 사용자가 직접 쓴 문장을 구분하려면 문맥을 이해해야 하므로, 이 판단은 모델에 맡겼습니다. (설계 결정 4번)
- **판별 설정값은 전체 오탐률 대신 범주별 조건으로 골랐습니다.** "오탐률 10% 이하"라는 처음 기준으로 고른 설정은 `跑local server.`처럼 영어 단어를 섞은 중국어 문장을 놓쳤습니다. 오탐과 미탐의 비용이 범주마다 다르다고 보고 기준을 바꾸었으며, 처음 기준과 바꾼 이유를 함께 기록했습니다. (설계 결정 12번)
- **교정 결과는 작업을 마친 뒤 최종 답변의 맨 앞에 씁니다.** 평가에서 Sonnet이 고칠 부분을 진행 메모에만 적고 교정 블록을 출력하지 않는다는 사실을 확인한 뒤, 출력 위치를 바꾸었습니다. (설계 결정 13번)

### 평가 결과 요약

- **중국어 판별**: 문장 122개를 조정용 85개와 확인용 37개로 나누었습니다. 설정값은 조정용 세트로만 고르고, 확인용 세트는 설정값을 정한 뒤에 한 번만 실행했습니다. 확인용 세트에서 기본값의 재현율은 0.909(20/22)였습니다. 오탐률은 0.467(7/15)로 높게 나왔는데, 판별하기 어려운 문장을 데이터셋에 일부러 많이 넣었기 때문입니다. 실제로 가장 많이 들어오는 한국어 요청과 영어 요청에서는 전체 데이터셋에서 오탐이 하나도 없었습니다.
- **교정 품질**: 케이스 33개를 Sonnet 5.5와 Opus 5.5로 케이스마다 3회씩 실행하고, 정규식 채점자로 출력 형식과 동작을 채점했습니다. 첫 평가에서 Sonnet은 오류가 있는 문장 45회 중 4회에서만 교정 블록을 출력했습니다. `SKILL.md`를 고친 뒤 실행한 최근 평가(2026-10-30)에서는 형식 준수 통과율이 Sonnet 0.210에서 0.959로, Opus 0.906에서 1.000으로 올랐습니다.
- 정규식 채점자로는 교정 설명의 내용이 맞는지 확인할 수 없습니다. 이 부분은 다음 단계에서 LLM 채점자로 평가할 계획입니다.

### 기록 문서

평가 방법과 전체 수치, 결정마다 검토한 대안은 `docs/` 폴더에 기록했습니다. 처음 읽는다면 다음 두 문서부터 보는 것을 권장합니다.

- [설계 결정 기록](docs/design-decisions.md): 판별을 훅에서 코드로 처리한 이유, 판별 설정값을 고른 기준, 교정 결과의 출력 위치처럼 설계할 때 내린 결정을 기록했습니다. 결정마다 검토한 대안과 감수한 트레이드오프를 함께 적었습니다.
- [평가 결과](docs/eval-results.md): 중국어 판별 정확도와 교정 품질을 평가한 결과를 기록했습니다. 평가마다 날짜, 대상 커밋, 모델, 수치를 적어서, `SKILL.md`를 고치기 전과 후의 결과를 비교할 수 있게 했습니다.

`docs/`의 `eval-6-3-*` 문서는 교정 품질 평가를 진행하면서 남긴 중간 기록입니다. 평가 결과 문서에서 각 단계의 세부 내용이 필요한 곳마다 이 문서들을 안내합니다.

## 개발하기

### 동작 방식

1. `UserPromptSubmit` 훅이 입력된 프롬프트를 검사하여 중국어인지 판별합니다. 판별 기준은 [중국어 판별 기준](#중국어-판별-기준)에 정리했습니다.
2. 중국어라고 판별되면, 훅은 `proofread` 스킬을 먼저 적용하라는 지시를 Claude의 컨텍스트에 추가합니다.
3. Claude는 `proofread` 스킬에 정의된 절차에 따라 교정된 의미를 기준으로 원래 요청을 수행하고, 최종 답변의 맨 앞에 교정 블록을 출력합니다. 출력 형식은 [교정 결과 예시](#교정-결과-예시)에서 볼 수 있습니다.
